# Unified IDP Camp Management System - AI Coding Context

## Goal
Build a full-stack web MVP for managing IDP camps, camp-level aid contributions, receipt confirmations, complaints, and reports.

## Tech Stack
- Framework: Next.js Full Stack, App Router
- Language: TypeScript
- Database: Neon PostgreSQL 18
- ORM: Drizzle ORM
- Migration Tool: drizzle-kit `^0.31.7`
- Validation: Zod
- Authentication: Auth.js / NextAuth or a secure custom JWT/session implementation
- Styling: Tailwind CSS
- UI components: shadcn/ui or equivalent reusable components
- API style: Next.js Route Handlers or Server Actions, but all protected operations must be authorized on the server

## Database Notes
- Neon is PostgreSQL, not MySQL.
- Do not use Prisma.
- Use `drizzle-orm` and `drizzle-kit`.
- Use `postgres` or `@neondatabase/serverless` depending on the runtime strategy.
- Keep database schema in `src/db/schema`.
- Keep database connection in `src/db/index.ts`.
- Keep migrations in the Drizzle migrations folder generated by drizzle-kit.
- Use PostgreSQL-compatible types and SQL only.

## Dashboard Template Decision: NextAdmin

Use the NextAdmin dashboard template from Next.js Templates as the UI/dashboard foundation.

### Important Rules
- Do not build a custom dashboard layout from scratch if the template already provides one.
- Preserve the template's existing layout, sidebar, header, theme, dark mode, responsive behavior, cards, tables, forms, and chart components where possible.
- Implement the IDP Camp Management features inside the existing NextAdmin app structure.
- Adapt routes, sidebar items, and pages to the project modules.
- Replace demo/sample data with real data from Neon PostgreSQL 18 through Drizzle ORM.
- Keep reusable UI components consistent with NextAdmin's component style.
- If the template already includes Auth.js/NextAuth patterns, reuse and adapt them instead of creating a conflicting auth system.
- If the template includes prebuilt chart/table/card components, use them for dashboards and reports.
- Keep code identifiers in English. User-facing labels may be Arabic or English depending the selected package language.

## Database and Tool Versions
- Use Neon PostgreSQL 18.
- Use `drizzle-kit` version `^0.31.7`.
- Use Drizzle ORM with PostgreSQL only.

## Critical Scope Rule
Aid is managed at camp level only.
Do not implement aid distribution to families or individual beneficiaries.
Families exist only for statistics and population reporting.

## MVP Actors
1. System Administrator
2. Camp Manager
3. Humanitarian Organization Representative
4. Independent Aid Initiator
5. Beneficiary / Displaced Person

## Core Authorization Rules
- Never rely only on hidden frontend buttons.
- Every protected mutation and query must enforce server-side permissions.
- System Administrator can access all system data.
- Camp Manager can access only assigned camps.
- Providers can access only their own provider profile and contributions.
- Beneficiaries can submit and track complaints using public forms only.

## Status Enums
Use PostgreSQL enums with `pgEnum` or text columns with Zod validation:
- user_status: active, inactive
- user_role: system_admin, camp_manager, org_representative, independent_initiator
- camp_status: active, inactive, closed
- need_level: low, medium, high, critical
- provider_type: organization, independent_initiator
- contribution_status: draft, submitted, cancelled
- contribution_line_status: pending, received, partially_received, not_received, rejected
- complaint_type: complaint, suggestion, unmet_need
- complaint_status: pending, in_review, resolved, rejected
- notification_status: unread, read

## Global Development Rules for AI Agent
- Implement each phase independently and make sure the app runs after every phase.
- Prefer small, typed, reusable modules.
- Keep business logic in service functions, not directly inside UI components.
- Add Drizzle migrations for every schema change.
- Add seed data where useful.
- Add clear empty states, loading states, and validation messages.
- Do not implement excluded features unless explicitly requested.
- Keep Arabic labels possible in UI, but internal code identifiers should be English.

## Excluded from MVP
- Family-level aid distribution
- Recording that a family received aid
- Beneficiary signature
- GPS/GIS mapping
- Financial/accounting module
- External integrations
- Offline sync
- Mobile app
- Complex automatic need classification
- Inventory decrement per family

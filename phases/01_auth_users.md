# Phase 01 - Authentication, Authorization, and User Management

## Objective
Implement secure login, logout, role-based routing, server-side authorization, password changing, and admin user management using **Better Auth** (Email + Password only).

## Scope
- User model (extended with Better Auth schema).
- User status managed via Better Auth's `banned` field (replacing custom `status`).
- Login page (Email + Password).
- Logout action.
- Protected dashboard layout via middleware and session checks.
- Server-side permission utilities (Better Auth `admin` plugin).
- Admin user list.
- Create user.
- Edit user (custom route/action for non-plugin fields like `fullName`, `phone`).
- Deactivate user (Ban/Unban).
- Prevent deactivation of last active admin (custom hook in Better Auth or route).
- Change password.

## Roles
- `admin`
- `user`

Beneficiary is public and does not need a full system account in MVP.

## Core Models
- **User** (Better Auth base + custom fields)
  - `id`
  - `name` (maps to fullName conceptually, or add `fullName` specifically)
  - `email`
  - `emailVerified`
  - `image`
  - `banned` (from admin plugin, acts as active/inactive status)
  - `banReason`
  - `banExpires`
  - `phone` (Custom)
  - `role` (Admin plugin natively supports `admin` | `user`)
  - `createdAt`
  - `updatedAt`
- **Session**, **Account**, **Verification** (Generated by Better Auth CLI)

## Authorization Rules
- Backend authorization is mandatory.
- Unauthenticated users are redirected or rejected.
- Authenticated users without permission receive Forbidden.
- Banned users cannot log in (handled by Better Auth).
- Role changes affect permissions immediately after next request/session refresh.
- Redirect after login: `/dashboard`.

## Technical Implementation Notes
- **Drizzle ORM:** Define tables using `pgTable` and PostgreSQL column types.
- **Better Auth Config:** 
  - `src/lib/auth.ts`: Setup `betterAuth()` with `drizzleAdapter` + `admin()` plugin.
  - `src/lib/auth-client.ts`: Setup `createAuthClient` with `adminClient` plugin.
  - `src/app/api/auth/[...all]/route.ts`: Better Auth handler.
- **Middleware:** `src/middleware.ts` to protect `/dashboard/*`.
- **Seeding:** Create initial `admin` via `seed.ts`.

## UI Pages
- `/login`
- `/dashboard`
- `/dashboard/users`
- `/dashboard/users/new`
- `/dashboard/users/[id]/edit`
- `/dashboard/settings/change-password`

## Acceptance Criteria
- Active admin can log in and reach Dashboard.
- Active user can log in and reach Dashboard.
- Invalid credentials show generic error.
- Banned account is blocked from login.
- Logout invalidates session/token.
- Admin can create users.
- Admin can edit user details (name, phone, role).
- Admin can ban/unban users.
- Last active `admin` cannot be banned.
- User can change password with current password validation.
